# Offline support and updates

Sustain-a-Pet uses one service worker, generated by `vite-plugin-pwa` (`generateSW`, config in `vite.config.js`).
Do not add a second worker.

## What works offline
After one online visit the app reopens with no network:
- **Precached at install:** `index.html`, all hashed JS/CSS in `/assets/`, fonts, icons, manifest, audio (38 entries, about 1.9 MB).
- **Cached on first use (CacheFirst):** `/models/*.glb` and `/textures/*`. A model the user never loaded online is not available offline; the 2D fallback garden is used if it fails.
- **Deep links** (any URL without a file extension) are answered from the cached `index.html` (`navigateFallback`).
- **`/api/*` is never cached or intercepted.** It goes straight to the network and fails naturally offline, so the client shows its offline state and disables only AI quest generation (see `src/resilience.js`).

## Registration
`src/pwa.jsx` registers the worker only when `import.meta.env.PROD` is true. `vite dev` never registers one. Playwright tests block workers (`serviceWorkers: 'block'`) unless a test is about offline behavior.

## Caches and cleanup
- Precache: `sustain-a-pet-precache-v2-<origin>`, revisioned per file. Outdated entries are removed on activate (`cleanupOutdatedCaches`).
- Runtime: `sustain-a-pet-pet-models-<CACHE_VERSION>` and `sustain-a-pet-pet-textures-<CACHE_VERSION>`.
- `public/sw-extra.js` (loaded with `importScripts`) deletes older runtime cache versions on activate.
- To invalidate runtime caches: bump `CACHE_VERSION` in `vite.config.js` and the `CURRENT` list in `public/sw-extra.js`. `tests/serviceWorker.test.js` fails if they differ.

## Update behavior ("prompt" mode)
1. A deploy changes `sw.js`. The browser installs the new worker in the background. It does not call `skipWaiting` by itself.
2. The running page keeps the old worker and its old hashed chunks, so lazy chunks never 404 mid-session.
3. `UpdateNotice` shows a small banner, "A new version is ready.", with **Reload** and dismiss buttons.
4. Reload sends `SKIP_WAITING`. The new worker activates, claims clients, removes old precache entries, and the page reloads.
5. If the user ignores the banner, the new version applies on the next full close and reopen of the app.

Why not auto-update: `skipWaiting` + `clientsClaim` deletes the old precache while the open page may still import chunks from it. The prompt avoids that.

## Server headers
Set in `server/index.js` (`cacheControlFor`), `public/_headers` and `netlify.toml`:
- `/sw.js`, `/sw-extra.js`, `/registerSW.js`, `/manifest.webmanifest`, `/index.html`, `/`: `Cache-Control: no-cache` so updates are found.
- `/sw.js`: `Service-Worker-Allowed: /` (worker at the root, scope `/`).
- `/manifest.webmanifest`: `application/manifest+json`.
- `/assets/*`: `public, max-age=31536000, immutable`.

Manifest icons (`/icons/icon-192.png`, `icon-512.png`, `icon-maskable-512.png`) exist in `public/icons/`; a test checks this.

## Manual check
1. `npm run build`, then start the production server.
2. Open the app, wait a few seconds, reload once so the worker controls the page.
3. DevTools, Network: set Offline. Reload and open a deep link such as `/anything`. The app shell loads.
4. In the offline app, request an AI quest. It fails with the offline message and nothing else breaks.
